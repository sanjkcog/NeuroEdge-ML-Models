## Arguments

```
$ARGUMENTS:
  <prd-path>     Path to PRD file (default: neuroedge/docs/project_related/<objective-slug>/02-project-plan/PRD.md)
  --epic EP-NN   Regenerate only a single EPIC by ID (e.g. --epic EP-03)
  --update       Append stories only for phases not yet present in the output file
```

---

## Phase 0 — DETECT

Resolve the PRD source from `$ARGUMENTS`:

| Input pattern | Action |
|---|---|
| Path to `.md` file | Use directly as PRD source |
| `--epic EP-NN` flag only | Load existing output file; regenerate the named EPIC |
| `--update` flag only | Load existing output file; find EPICs whose phase is `pending` |
| Empty / blank | Look for `neuroedge/docs/project_related/<objective-slug>/02-project-plan/PRD.md` — use if found, else ask the user |

Once PRD path is resolved, read the full file before proceeding.

If the PRD contains `Status: DRAFT` or `needs validation`, output this warning before proceeding:

> ⚠ PRD status is DRAFT. Output will reflect current scope but may change after validation.

---

## Phase 1 — PARSE

Extract and summarise the PRD structure to confirm scope before writing stories. Sections are matched by heading
content/intent (e.g. "Core Capabilities (MoSCoW)", "Users & Context", "Implementation Phases", "Success Metrics",
"Open Questions"), not by numbered section labels — PRDs generated by `/prp-prd` don't number their headings.

**FR backfill (legacy PRDs):** If the "Core Capabilities (MoSCoW)" table exists but its rows carry no `FR-NN`
codes (a PRD written before FR numbering was added to `/prp-prd`), assign them now, in table order — all Must rows
first, then Should, then Could, then Won't, starting at FR-01. **Edit the source PRD file in place** to add the
codes (an `FR` column plus the codes themselves) so the PRD stays the single numbering authority rather than the
codes only existing in this command's output. Note the backfill in the Phase 1 summary below.

```
PRD: <filename>
Personas found:      <count> — <comma-separated names from "Users & Context">
Phases found:        <count> — <phase IDs and titles from "Implementation Phases">
FR codes found:      <count> — FR-01…FR-NN from "Core Capabilities (MoSCoW)" (note if backfilled)
MUST capabilities:   <count>
SHOULD capabilities: <count>
Success metrics:     <count> — from "Success Metrics"
Open questions:      <count blocking> — from "Open Questions"
Output file:         neuroedge/docs/project_related/<objective-slug>/02-project-plan/epics-and-user-stories.md
```

Print this summary and wait for the user to confirm before generating.

**GATE:** If personas are missing OR no phases are found, stop and report what is absent. Do not generate without
them. Missing FR codes alone are not a stop condition — backfill them per the rule above and continue.

---

## Phase 2 — DECOMPOSE

Spawn the `epic-writer` agent with the PRD file path and any scope flags (`--epic`, `--update`). Pass along the
resolved `FR-NN` codes from Phase 1 (including any just backfilled) so the agent cites them directly.

The `epic-writer` agent will:
1. Map each phase to an EPIC with goal, priority, and plan link
2. Group functional requirements into user stories under each EPIC
3. Write acceptance criteria traceable to FR codes and success metrics — cite the exact `FR-NN` code from the PRD
   (not a paraphrase of the capability name) in every AC that implements it, so a search for `FR-06` finds every
   story/AC that depends on it
4. Validate coverage against the checklist in the `prd-decomposition` skill
5. Return the complete EPIC + story markdown and a coverage check table

Write the output to `neuroedge/docs/project_related/<objective-slug>/02-project-plan/epics-and-user-stories.md`.

**`--epic EP-NN`** — replace only the matching `## EP-NN` section in the existing file; preserve all other sections.

**`--update`** — append new EPICs for phases not yet present; do not modify existing EPICs.

## Integration with PRP Workflow

```
/prp-prd   → produces PRD
/prd-to-epics   → this command: produces EPICs + stories from PRD     ← you are here
/prp-plan  → produces phase implementation plan (references story ACs as acceptance criteria)
/prp-implement  → executes the plan step by step
/prp-pr    → opens a reviewed PR
```

Stories produced by this command feed directly into `/prp-plan` as the acceptance criteria for each implementation plan. When writing a plan, reference the story ID (e.g., `US-01-02`) to trace from plan step → story AC → PRD FR.
