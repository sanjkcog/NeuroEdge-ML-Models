**Leakage-safe split rule (KIT, the pick):**
- **Grouping unit: experiment** (33 independent milling experiments, each identified by component type + trial ID).
- Split **by experiment, not by window** — no sliding window from one experiment may appear in more than one of train/val/test.
- Within an experiment, if further windowing is needed, keep windows chronological (no shuffle across the DOC/feed/material regime of that run).
- **Cross-machine hold-out:** the entire Bosch CNC_Machining dataset (a different machine, different sensor set) is held out — never blended into KIT's train fold — to test whether a model trained on KIT generalizes to vibration-only signal on a different mechanical structure. This is a hold-out for **honesty about single-machine risk**, not a substitute training source (its channel set does not match the 3-channel contract).
- Fit any normalization (mean/std) on the KIT train-fold experiments only, per `time-series-ml` rule 3.

## 3. Known caveats (stated plainly)

- **Single-machine risk (primary pick):** all 33 experiments are on one physical machine (DMC 60 H). This is the single biggest external-validity risk — the Bosch hold-out only partially mitigates it (different machine, but vibration-only, so it cannot validate the `x_axis_error` or `spindle_load` channels transferring).
- **`x_axis_error` may not be nativeley recorded.** The publicly readable KIT metadata confirms an axis "position" signal exists but does not confirm two separate commanded/actual streams are exposed — this is the single largest open risk item for the stated channel contract and must be resolved by inspecting the actual data package in M2 (`/dataset-verify`), before `ml-modeler` commits to this exact 3-channel input shape.
- **Anomaly-type counts are unknown pending download.** The record states "8 anomaly types" across "3 component types" over 33 experiments in aggregate, but per-class counts, and how many experiments are "normal" vs "anomalous," are `TBD` — this determines whether class imbalance requires `/synth-data` augmentation of the rare anomaly types before training.
- **32 vs 33 experiment count:** the RADAR record's own text says 33; I could not access the companion Data in Brief paper (paywalled) to check whether it states 32, so I cannot confirm or refute the discrepancy flagged in the prior (deleted) scouting pass. Do not resolve this by picking one number — get the actual data package's directory count at M2.
- **Continuous drift-score label does not exist as such.** KIT provides discrete anomaly-type/severity labels per experiment (not a continuous 0–1 drift score); a continuous drift score for the edge model's output will need to be **derived** (e.g. distance-to-normal-manifold, or a monotonic mapping from labeled severity), which is `ml-modeler`'s job, not scouted here — flag it as a design decision, not a data gap.
- **Bosch hold-out is not free of its own limits:** only "good"/"bad" binary labels, no anomaly-type granularity, no spindle-load or axis-error channel — usable only as a coarse cross-machine sanity check, not for calibrating anomaly-type performance.
- **PHM 2010 and NASA Milling excluded, not because they are useless** — NASA Milling's spindle-current + vibration channels could become a secondary sanity/pretraining source later if its license is resolved to be usable, but it lacks the axis-error channel entirely, so it cannot replace the pick.

## 5. Readiness summary

The picked dataset is the **KIT multimodal CNC milling dataset** (Ströbel et al. 2025, KITopen/RADAR, DOI `10.35097/hvvwn1kfwf7qt48z`, CC BY 4.0 — independently confirmed commercial-use-safe from two locations in the rights holder's own record). It is the only real-industrial-machine candidate found that co-records axis-controller signals (needed to derive `x_axis_error`), spindle current/torque (`spindle_load`), and vibration/force (`vibration_rms`) on one machine, across 33 experiments spanning 3 component types and 8 anomaly types (per-class counts `TBD` pending download). No API key is required. The split unit is the **experiment** (33 independent units) — never the sliding window — with the entire **Bosch CNC_Machining** dataset (CC BY 4.0, no key required, vibration-only, 3 different machines) held out as a cross-machine generalization check, not blended into training. The chief open risk carried into M2 is whether the KIT controller export actually exposes both commanded and actual X-axis position (needed to derive `x_axis_error` as specified) — this must be resolved by inspecting the real CSV header before `ml-modeler` commits to the 3-channel input shape, and the single-machine origin of all 33 training experiments remains the primary external-validity caveat even with the cross-machine hold-out in place.
